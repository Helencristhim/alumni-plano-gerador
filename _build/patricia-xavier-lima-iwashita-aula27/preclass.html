Lesson 27 -- Pre-class

What Could Be Causing It?

Thinking out loud on a problem call before anybody knows the answer. Key words: hypothesis, rule out, narrow down, symptom, intermittent, error message, timeout, status page, expire, evidence. Structure: modals of deduction -- must, might, could and can't + be -- to say how sure you are, always with a reason.

Stage 1.1: Vocabulary Cards

Vocabulary

Listen to each word and read the example. Tap Listen to hear it.

Hypothesis -- an idea about the cause that you still have to test
"My hypothesis is that the file is too big."
Rule out -- to decide that something is not the cause
"The status page is green, so we can rule out the server."
Narrow down -- to reduce the number of possible causes
"Two questions helped us narrow down the problem."
Symptom -- a sign that shows you there is a problem
"The first symptom was a slow dashboard."
Intermittent -- happening sometimes, but not all the time
"The error is intermittent: it only happens at night."
Error message -- the text that a system shows when something fails
"The error message says "timeout" every time."
Timeout -- when a system stops waiting because a task takes too long
"The sync fails with a timeout after thirty minutes."
Status page -- a public page that shows if a service is working
"Always check the status page before you call engineering."
Expire -- to stop being valid after a fixed date
"The access token expires every ninety days."
Evidence -- facts that show if an idea is true
"I will send you the evidence before five o'clock."

Stage 1.3: Grammar in Context

GRAMMAR

Read the text and answer the questions.

On her third day with the new portfolio, Patrícia gets a call from Daniel at Brightwave Retail: the nightly sync has failed again. The problem is intermittent, so the first job is to narrow down the causes. The first symptom is simple: the orders are not there at seven. It can't be the users, because nobody is online at night. It can't be the server either, because the status page was green all night — so she can rule out two causes in one minute. The error message says timeout. It might be the access token, which expires every ninety days, but nobody has checked the date. And Brightwave added a new region on Monday, so the file must be much bigger now. That is her hypothesis, and she promises the evidence before five.

1. "It can't be the users." How sure is Patrícia?
A She is almost sure that the users are NOT the cause.
B She thinks the users are probably the cause.
C She has no idea.
2. "It might be the access token." Why does she use might?
A Because she has evidence.
B Because it is possible, but nobody has checked yet.
C Because it is not allowed.
3. Why can she rule out the server?
A Because the status page was green all night.
B Because Daniel told her.
C Because the token expired.
4. Which sentence is correct?
A "The file must to be bigger now."
B "The file must be bigger now."
C "The file musts be bigger now."

Stage 1.4: Grammar Tip -- Modals of Deduction: must / might / could / can't + be

GRAMMAR

How to say how sure you are, before you have the final answer.

StructureUseExample
must + beAlmost sure it is true. You have a reason.It must be the new region.
might / could + bePossible. You are not sure.It might be the token.
can't + beAlmost sure it is NOT true.It can't be the server.
might not + bePossibly not true.It might not be the file.
must be + -ingSomething happening now.The sync must be running now.
AvoidNever "to" after the modal: not "must to be" → "must be". Never -s or is: not "it might is" → "it might be". For deduction, the opposite of must is can't, never mustn't: "mustn't" means it is not allowed.

Stage 2: Run the Problem Call in Order

Order

Put the steps of a good troubleshooting call in the right order.

?Rule out the causes that are impossible, with a reason.
?Ask for the symptoms and the error message.
?Close with a next step and a time.
?Check the status page before you guess.
?Give your hypothesis: what it must or might be.

Stage 5: Free Production

Reflection

Record yourself answering the question below. There is no right or wrong answer.

Think of one real problem from your accounts -- a sync, an integration, a report with wrong numbers. Record yourself thinking out loud as if you were on the call with the customer, in five or six sentences: the symptoms, what you rule out and why, your hypothesis, and the next step with a time. Use must, might, could and can't, and give a reason every time. Take your time.
